# AgriRain — ML-Based Rainfall Prediction for Farmers

AgriRain is a local Flask college mini-project for ten Karnataka districts. It combines Open-Meteo forecast data with an experimental scikit-learn classifier and stores user accounts and each account's prediction records in SQLite. The weather forecast and model estimate are shown as separate outputs.

The first page is the login screen. A visitor can create an account with an email and password, then sign in. Passwords are stored as Werkzeug password hashes, not plain text. Prediction history is scoped to the signed-in account; records from the earlier anonymous demo remain unassigned and are not shown to any new account. State-changing forms require a session-bound CSRF token. Set `FLASK_SECRET_KEY` to a private, stable random value when you need sessions to survive app restarts; without it a fresh development secret is generated at process start.

## A. Architecture

1. The district selection is mapped to its latitude and longitude in `app.py`.
2. The Flask application requests the one-day Open-Meteo forecast. It shows minimum and maximum temperature, daily rainfall total, and relative humidity forecast at 3 PM local time.
3. The saved scikit-learn pipeline receives those four values in the training feature order: `MinTemp`, `MaxTemp`, `Rainfall`, `Humidity3pm`. Its label and, when available, positive-class probability are displayed as an experimental estimate.
4. Successful predictions are inserted once into SQLite. The POST/redirect/GET flow means refreshing the result page does not submit the form again.

The model is trained on Australian weather observations. A held-out split measures performance on that dataset only; this is **not validation for Karnataka**. Train on quality-controlled local observations and evaluate across seasons and districts before using this for real decisions. The model probability is an estimate, not a guarantee. This student demonstration has not had production security testing.

## K. Windows installation and run

Use PowerShell from the project directory. Python 3.13 is supported by current releases of the listed packages.

```powershell
# If starting from scratch, create and enter a folder first:
mkdir AgriRain
cd AgriRain

# Create and activate an isolated Python environment:
py -3.13 -m venv .venv
.\.venv\Scripts\Activate.ps1

# If PowerShell blocks activation for this terminal, use the venv interpreter directly:
# .\.venv\Scripts\python.exe -m pip install --upgrade pip

python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

Place `weatherAUS.csv` in `data\weatherAUS.csv` or in the project root. This workspace already has a root-level copy. Train the model once, then start the application:

```powershell
python train_model.py
python app.py
```

Running `python app.py` opens `http://127.0.0.1:5000/login` in your default browser (set `AGRIRAIN_OPEN_BROWSER=0` to disable this). The root URL also redirects signed-out users to login. Register a user, then sign in; successful login opens the main page. The main navigation has a Sign out button, and the dashboard has a confirmation-protected Clear history button. The SQLite database and tables are created automatically on startup. An internet connection is needed for Open-Meteo. If `py` or `python` is not found, install Python 3.13 from python.org, enable the PATH option in the installer, reopen PowerShell, and check `py --version` and `python --version`. If `pip` is unavailable, invoke it as `python -m pip`.

## L. Database schema

`prediction_history.db` is created in the same folder as `app.py`. `prediction_history` has these fields:

| Field | Meaning |
|---|---|
| `id` | Automatically increasing record key |
| `user_id` | Owning account; nullable only for anonymous records migrated from the old demo |
| `district` | Selected district |
| `prediction` | Model output label |
| `rainfall_probability` | Optional positive-class probability from `predict_proba` |
| `temperature_min`, `temperature_max` | Forecast temperatures in °C |
| `expected_rainfall` | Daily forecast total in mm |
| `humidity` | Relative humidity forecast at 3 PM local time in percent |
| `created_at` | Local time with timezone offset |

The `users` table stores a unique case-insensitive email, a password hash, and account creation time. Each prediction row has a `user_id` foreign key. The app filters history and deletion by the authenticated account.

The original demo `history` table is copied into the new schema at startup; old rows have `NULL` for weather columns. To verify saved rows while the app is stopped, use Python:

```powershell
python -c "import sqlite3; c=sqlite3.connect('prediction_history.db'); print(c.execute('SELECT id,district,prediction,created_at FROM prediction_history ORDER BY id DESC LIMIT 10').fetchall()); c.close()"
```

The history page displays 20 rows at a time and has a confirmation dialog before deletion.

## M. Dataset download

Download `weatherAUS.csv` from Kaggle's [Rain in Australia dataset](https://www.kaggle.com/jsphyg/weather-dataset-rattle-package). Sign in if Kaggle requires it, download the dataset archive, extract `weatherAUS.csv`, and place it in `data\weatherAUS.csv` (or the project root). The dataset represents Australian daily weather and its `RainTomorrow` label. Its geography and climate differ from Karnataka, so its scores and probabilities must not be interpreted as locally validated performance.

## N. Model training

Run `python train_model.py`. It checks required columns, parses dates, converts malformed feature values to missing values, and keeps only `Yes`/`No` target labels. It holds out the newest 20% of distinct dates for evaluation, fits median imputation and a Random Forest pipeline on earlier data, reports accuracy/precision/recall/F1 and a confusion matrix, then refits the deployment pipeline on all valid labelled rows and writes it to `rainfall_model.pkl`. The chronological holdout prevents training on later rows while evaluating earlier ones. Training reads the same four forecast features requested by the app; no fabricated samples are created.

This chronological holdout is still only an Australian dataset assessment, not a Karnataka validation or a substitute for station-based verification. A better local model requires matching local observations and future rainfall labels; avoid future-observation leakage when constructing those features.

## O. Practical testing checklist

- [ ] Opening `/` while signed out redirects to the login page.
- [ ] Register with an email, a password of 8 or more characters, and a matching confirmation; the password is stored as a hash.
- [ ] Duplicate email and mismatched passwords are rejected with a friendly message.
- [ ] Sign in with the new account, then sign out.
- [ ] Send a POST without a CSRF token; the server should reject it with HTTP 400.
- [ ] Try an SQL-like string as a login email; it must not authenticate or alter database contents.
- [ ] Create records under two accounts and confirm each account sees and clears only its own records.
- [ ] Home page loads and navigation links work.
- [ ] Each of the ten districts can be selected.
- [ ] Open-Meteo values and forecast date are shown when available.
- [ ] Submit a prediction after training; see the result and any model probability estimate.
- [ ] Confirm the corresponding row exists in SQLite using the query above.
- [ ] Open Prediction history, paginate if needed, and refresh; saved records remain.
- [ ] Press Clear history and cancel; rows remain. Confirm the action; rows are removed.
- [ ] Submit a tampered district value; no prediction should be stored.
- [ ] Temporarily disconnect from the network; a friendly forecast error appears and the server remains available.
- [ ] Rename the model file temporarily; the app shows the retraining instruction instead of crashing.
- [ ] Test narrow/mobile viewport; cards and tables remain usable (tables can scroll horizontally).

Automated test command: `python -m unittest discover -s tests`. (Test files are included in `tests/`.)

## P. Common issues

| Symptom | Fix |
|---|---|
| `Dataset not found` | Put the extracted file at `data\weatherAUS.csv` or project root. |
| `No module named ...` | Activate `.venv`, then run `python -m pip install -r requirements.txt`. |
| Login rejects the account | Check the email spelling and password; passwords are case-sensitive. Register again only with a different email if the address already exists. |
| User is signed out after restarting Flask | For a stable development session key, set `FLASK_SECRET_KEY` before starting Flask. |
| Model missing or invalid | Run `python train_model.py` in the project directory. |
| Weather unavailable | Check internet access and try again; no substitute data is generated. |
| Port 5000 is in use | Stop the other local Flask process, then retry. |
| PowerShell blocks venv activation | Use `.\.venv\Scripts\python.exe -m pip ...` and `.\.venv\Scripts\python.exe app.py` directly. |
| Prediction shown but not in history | Check that the project directory is writable and inspect `prediction_history.db`; the database is next to `app.py`. |

Flask's built-in server is for local development and demonstration only. It does not include login rate limiting or production HTTPS configuration. Do not deploy this app as a public production service without security, privacy, and operational review.

## Render deployment

The repository includes `render.yaml` for a Render free Python web service. It pins Python and the model's scikit-learn dependencies, serves the app with Gunicorn, enables secure session cookies, and stores SQLite under `/tmp`.

Render's free service has an ephemeral filesystem, so accounts and prediction history may be lost when the instance restarts or redeploys. The deployed database starts separately from the local `prediction_history.db`; local accounts and history are not uploaded. Create a new account on the deployed site. Do not store important or sensitive data in this demo deployment. Persistent SQLite storage on Render requires a paid web-service plan; this Blueprint does not configure a paid plan or disk.

Official instructions: [Deploy a Flask App](https://render.com/docs/deploy-flask), [Persistent Disks](https://render.com/docs/disks), and [Blueprint Specification](https://render.com/docs/blueprint-spec).
